# Report Excel Export Implementation Report

## Scope

This implementation completes Excel export for the existing Reports module without changing business rules, UI layout, or report API response contracts.

Export data source rule:

- Excel export uses `ReportService` DTOs as the source of truth.
- Excel generation does not recalculate report business logic.
- Manager exports use backend manager store scope and ignore frontend `storeId`.
- Admin exports keep the existing optional store filter.

## Export APIs

Admin:

- `GET /api/v1/admin/reports/export/excel`

Manager:

- `GET /api/v1/manager/reports/export/excel`

Query parameters:

- `reportType`
- `fromDate`
- `toDate`
- `storeId` for admin only
- `paymentMethod`
- `orderStatus`
- `keyword`

Supported `reportType` values:

- `revenue`
- `orders`
- `payment`
- `inventory`
- `goods-receipt`
- `consumption`

Response:

- Content type: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- Header: `Content-Disposition: attachment; filename="...xlsx"`
- Body: `.xlsx` binary

## Excel Structure

Each workbook contains one sheet:

- Revenue Report
- Orders Report
- Payment Report
- Inventory Report
- Goods Receipt Report
- Ingredient Consumption Report

Each sheet includes:

- Report title
- Generated time
- Generated by
- Date range
- Store scope
- Filter summary
- Header row
- Data rows
- Freeze pane at the table header
- Number, currency, date, and datetime formatting

The Excel files intentionally do not include:

- Logo
- Watermark
- Hidden formulas
- Export-only business calculations

## Report Integration Flow

Frontend flow:

1. User opens the existing admin or manager reports page.
2. User selects report tab and filters.
3. User clicks `Export Excel`.
4. Frontend calls the proper admin or manager export endpoint.
5. Backend calls the matching `ReportService` method.
6. Export service serializes returned DTO data to `.xlsx`.
7. Browser downloads the file using backend filename.

Backend source-of-truth flow:

1. Controller validates report type and scope.
2. Controller calls `ReportService`.
3. `ReportService` applies existing business rules and manager/admin scope.
4. `ExcelExportService` only writes DTO fields into workbook rows.

## Permission Verification

- Both export endpoints require `REPORT_VIEW`.
- Admin export supports global data and optional `storeId`.
- Manager export uses manager-scoped `ReportService` methods.
- Manager `storeId` override from query string is not accepted by the manager endpoint.

## Remaining Issues

- PDF export remains out of scope and disabled in the UI.
- Very large exports currently use in-memory `XSSFWorkbook`; if report rows grow into hundreds of thousands, replace with `SXSSFWorkbook` streaming.
- Existing report pagination is not redesigned in this sprint.
- Export audit log is still available through the existing log endpoint, but the new Excel download endpoints do not create a separate export log row.
